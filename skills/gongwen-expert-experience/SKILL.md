# Experience Reports and Case Writing

Use for `experience-draft`, `summary-draft`, and `exchange-draft` factual sections. Choose one evidence-backed thread from the current facts. Organize it around the original problem, specific change, and observed result. Make methods understandable in peer exchanges and emphasize the key result in short submissions. Follow any submission structure the user specifies. Keep the organization, year, process population, and affected group with their results. Use a separate final section for proposed follow-up where required by intake.

- Explain the mechanism first, including combined steps, the flow of materials, and what applicants actually do. Show how separate entry points converge. Report uptake separately. Give each paragraph one main job.
- When the user wants the service process first and a case second, open with the concrete change in service. Put overall rollout data after the mechanism and separate it from the case outcome.
- Separate aggregate statistics, pilot comparisons, and individual cases. If requested, include the source name, reporting period, scope, and units at the first mention of each key figure. For periods with different totals, preserve each numerator and denominator. Include explicitly sourced calculations only when the project supports them and they help comparison. Without a valid comparator, report the observation on its own.
- Preserve express metric exclusions, such as 「办理件数不等于服务人数」. If the user asks what was verified, say which unverified items the sources exclude from outcomes. A case record supports only its observed action and elapsed time. Same-day completion does not establish immediate response or a general deadline.
- Extract transferable practices from a supported mechanism. Avoid unsupported attribution, scope, and claims of effectiveness. Omit the task assignment table.
- For a party branch or experience exchange, trace one supported action chain from discovery of a need to handoff and documented result. Stop where the records stop, including visits, discussions, or suggestions. For a periodic review, name which records to reconcile, distinguish inquiries, intake, and completion, and specify reporting cutoffs and relevant denominators. Write planned verification as a proposal.
- Read back every numerical paragraph during review. Check the population, unit, and qualifiers. Remove repetitive uses of the same data.

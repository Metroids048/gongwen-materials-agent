# Official Document Writer

Choose the document type from its audience, purpose, issuer, and intended action. Determine whether the user wants to report past work, plan new work, discuss options before a meeting, inform recipients, or revise an original. Borrow style from samples. Ground actual facts and commitments in current sources.

Resolve questions from this conversation, the current materials, and verified public facts supplied by the host. Use host-calculated dates when the user asks for a deterministic offset. If one consequential decision remains, ask once and use the prior answers on the next turn. For optional details, leave an explicit blank or record a review note and keep drafting. If the user chooses a working draft, keep any unconfirmed assumption visible. Deliver Chinese copy and messages unless the user requests another language.

For a plan, reconcile each action, responsible unit, timing, and deliverable across the prose and task table. Put the units named for that action in `lead`, including joint responsibility. Keep organizers separate from trainees, participants, and service recipients. List overall implementation as its own responsibility. Do not assign it to each subtask. Preserve named responsible units even if the lead is undecided. When the source calls for a report, record, or corrective action, name it as a deliverable and leave unrelated unknown fields open. Check adjacent items separately for owner, date, and scope.

Check any expert brief against primary evidence. A brief is a writing aid, not a new source or an exhaustive list. Before export, check the document type, coverage, field ownership, pending items, and consistency between the prose and tables.

Use [Plans](../gongwen-expert-plan/SKILL.md), [Experience reports](../gongwen-expert-experience/SKILL.md), or [Notices](../gongwen-expert-notice/SKILL.md) as appropriate. Use [Controlled revision](../gongwen-expert-revision/SKILL.md) for an editable original with explicit changes.

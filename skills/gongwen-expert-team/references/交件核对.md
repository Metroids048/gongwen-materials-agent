# Delivery Review

Review independently. Start from the user's intended use and original evidence. In the rendered responsibility column, check named units, leads, delivery parties, and service recipients. Verify that conditional reports appear as deliverables and do not acquire an invented owner. Check adjacent tasks for cross-assigned units. Leave unknown timing, thresholds, and organizers open. If the prose is right and the table is wrong, target the table. Use current anchors and name decisions for human review.

Copy `checked_ids` and `target_ids` from the allowed positions exactly. Include positions actually checked even when no defect was found. Use `TASKS` for missing task rows, not captions, source IDs, or invented positions. Copy the full current `basis_key` verbatim.

If an established training, service, or reporting obligation appears only in a `proposal` paragraph, report `blocking` and move it to an anchored `fact` paragraph. Meeting decisions can stay pending. If an overall implementation unit appears only in prose, target `TASKS` to add an overall row without assigning it as individual lead. If the user requests an output whose format, retention, or confirmation is pending, show that status in the relevant table row and suggest the smallest correction.

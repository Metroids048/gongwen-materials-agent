# Notices and Administrative Communications

Use for `notice-draft`. Deliver an editable review copy. An instruction to seek approval belongs in a request for approval. Detailed implementation may belong in a work plan. Apply the intake rules for official letterheads, document numbers, seals, and authorized templates.

- Name the matter in the title. Use a section with an empty heading for the addressee and introduction, one paragraph each. Express a colloquial recipient in formal language without expanding its scope. Open with the decision or action readers need to know, without repeating the heading or adding an unsupported rationale. For a single event, include the audience, time, location or online channel, activity, how to participate, and any relevant contacts or attachment fields with current evidence.
- Keep each session's audience, date and time, channel or meeting ID, and activity together in one section. List shared requirements separately, such as sign-up or arrival time. Use the information for the correct session.
- If the user needs actionable registration or a response form, include who submits, per-session capacity, deadline, channel, recipient, and requested fields when supplied. Report an existing roster submission as the attendees' organization returning its form. Recipient acknowledgment, late registration, and changes belong in the text only when specified. Put missing optional details in `review_notes`.
- When the user asks to compare multiple sessions and the five fields are known, use one paragraph per row with the exact format 「场次｜参加对象｜时间｜地点或线上渠道｜主要内容」. Omit the header row. The host renders an editable table. Use short grouped paragraphs for one session or incomplete rows.
- If requested response fields are known, tell readers to return the attached form. Keep the channel open if unsupplied. After the signature, include only one section titled 「报名回执」. It contains one `fact` paragraph with the supplied field names in order, separated with full-width 「｜」, and anchors to the actual source. Omit data rows and extra fields. The host builds the editable table. A reply from the receiving organization alone does not call for this form.
- If the fields include 「场次」 and the notice has a session table, the host displays that session's date, time, and location or channel alongside the form. Do not add those as new user-entry columns. Include the session table if the user supplies the full schedule and requests the form.
- Put the confirmed issuer and drafting date in separate paragraphs in a final untitled section, before any response form. Do not use a source publication date as the current signing date. If the signing date is missing, use the issuer alone or put 「成文日期：」 in a separate paragraph. Leave missing optional information in review notes. Keep body paragraphs with actual text.
- For relative dates, use host-provided calendar arithmetic tied to the user's request and a supplied or verified event schedule. “The day before and the day after” means two separate days unless the user requests a continuous period. If the event cannot be identified or the source conflicts, ask the remaining question once. If the user chooses a working draft, preserve relative wording or a clearly marked pending date. A day number alone does not establish the month or year. A public schedule establishes the event dates only. An issuer name does not establish that the arrangement has already been approved.
- Use only `fact` for body paragraphs, with actual source anchors, and keep `tasks` empty. Do not place review instructions, invented response requirements, or seals in the body.

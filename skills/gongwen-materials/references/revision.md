# Controlled Revisions

Confirm the actual current version, requested changes, authorized scope, and protected content. Return comments only when the user requests review without writing changes.

1. Map comments to paragraphs or tasks. Distinguish content, structure, length, facts, timing, responsibilities, wording, and formatting.
2. Preserve the parent, protected passages, figures, examples, and user edits. Use stable block IDs or another reliable location.
3. Apply changes within scope and check linked tables and repeated dates. If a necessary change would cross a lock, identify that location and ask only about the disputed scope.
4. Check each requirement, factual meaning, and any unauthorized differences. Wording similarity is not a factual test.
5. Before saving, check the parent version. Preserve both sides of concurrent changes and resolve the conflict. The user can authorize direct use of conflict-free revisions.

If “all dates stay the same” conflicts with a new deadline, identify the exact affected date and ask which instruction governs. Keep the unaffected material moving. Return the recommended revision with a short explanation of the actual changes and unresolved points. Continue later requests from the current version.
